# 【已实现】网络空间搜索引擎配置实现说明

2026-11-27 用户批准第一阶段，采用与 LLM 同一个 PostgreSQL 配置库。[需求评审](../review/【待用户审计】2026-11-27-网络空间搜索引擎需求评审.md) · [用户操作说明](../../docs/2026-11-27-网络空间搜索引擎.md)

- 系统「工具」下方提供配置入口。搜索引擎的列表与配置接口在现有 JWT 中间件后面。浏览器只能读取是否已设置凭据、配置修订和验证状态，凭据及账户标识留在服务端。[API 实现](../../server/cyberspace_search.go)
- 同一 PostgreSQL 实例的 `settings` 保存加密的供应商凭据及验证结果。独立 AES-GCM 密钥保存于 ARTEX 数据目录，权限为 `0600`，沿用 Docker 数据卷持久化。加密上下文绑定供应商及字段，防止错用供应商或字段的密文。部署迁移应保障密钥文件与数据库同步还原。[密钥实现](../../server/cyberspace_search_keys.go)
- 批量测试最多三个请求并发，进程内同时点击复用同一批次。连接使用固定供应商 HTTPS 地址、五秒超时、响应大小限制和禁用重定向，采用服务端直连。配置发生变化时，数据库条件写入使旧结果失效。传播到 UI 与日志的是固定原因码，供应商回包不输出。[账户检查](../../server/cyberspace_search_probes.go)
- FOFA、Shodan、ZoomEye、360 Quake、VirusTotal 和 SecurityTrails 提供账户检查适配。VirusTotal 缺少用户 ID 时显示未验证。奇安信鹰图、hunter.how 和 ProjectDiscovery Chaos 可配置和管理凭据，批量测试显示未验证。真实账户、套餐和出站部署条件仍待供应商逐家验收。

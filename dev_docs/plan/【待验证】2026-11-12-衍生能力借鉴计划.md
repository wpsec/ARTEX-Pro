# 【待验证】ARTEX 衍生能力借鉴与 Noa 评估

状态：Judge、finding 证据核验和 Noa 删除生命周期实现已完成；原生压缩/Noa 真实模型配对运行已执行，但回忆 JSON 不完整、结论不充分，仍需补充验证。评测后已在隔离实例 UI 关闭 Noa 并恢复 profile 原始限额。2026-11-26 因隔离实例 UI 出现不符合合成评测范围的内容，暂停新的模型调用，待核实数据隔离。详细结果见[评测记录](../review/【待验证】2026-11-25-真实模型行为评测记录.md)。

## 结论

- Noa 已通过 `norma/noaadapter` 接入 Planner、Worker、主 Agent 和平台对话。它可用于长上下文任务：当前请求压缩历史，完整原文仍留在归档中供 Agent 回读。技术上可落地，适合作为用户主动开启的实验选项。
- Noa 的摘要由模型生成，可能漏掉或误述细节；压缩时增加模型调用、token 和延迟；原文归档会持续占用磁盘。2026-11-25 已在同一模型、profile 和合成提示下运行原生压缩与 Noa 两组，但两组回忆输出都不完整；当前证据不能证明 Noa 提高了记忆准确率或漏洞检出率，也不支持默认开启。
- 本轮修复对话删除与 transcript、上传文件及 Noa 归档的生命周期脱节问题。Noa 的默认关闭状态保持不变。
- 衍生能力三项成本收益评审已完成。Judge 故障转人工和一次有界瞬时错误重试、finding 的证据引用匹配状态和可选反证说明已实现，CI/Release 使用的前端构建及应用包构建通过。脚本审批源码快照本轮不做；仅靠 hash 不能绑定实际执行内容，通用 shell 识别与执行端一致性成本高于目前可证明的收益。

## 衍生能力筛选

| 候选能力 | 本地缺口与收益 | 决定 |
|---|---|---|
| BaaRai：POE 等级、证据引用原文匹配、反证记录 | 可帮助审阅者定位支持或反驳结论；可复用已有 traffic snapshot 和 binding version。字符串匹配只证明引用可定位，不证明漏洞成立 | 已实现结构化原文匹配与可选反证；首版不加尚无 ARTEX 稳定定义的 POE 等级 |
| RuoJi6：脚本审批绑定路径、大小、SHA-256 与源码快照 | 让 Judge 看到直接脚本内容有审查价值；但跨解释器、复合 shell 和间接加载很难完整覆盖，hash 本身不保证执行同一字节 | 本轮不实现；待脚本调用数据证明高频且能界定执行绑定范围后再评估 |

| AntiFox：步骤化漏洞报告与流量关联 | 本地已有 finding、流量绑定、复测和报告，整套平台重复度高 | 只借鉴缺失的证据关联规则，不迁移平台架构 |

## Noa 收益与成本

| 方面 | 评估 |
|---|---|
| 可行性 | 已集成到现有 Agent 创建流程，不增加容器、数据库角色或默认工具 |
| 预期收益 | 长任务中减少重复携带的旧对话上下文；完整原文保存在会话归档，可按需取回细节 |
| 主要成本 | 需要额外模型调用生成摘要；增加 token、延迟和磁盘占用；摘要可能丢失因果、参数或授权上下文 |
| 隐私边界 | 归档含原始消息和工具输出，按运行用户限制目录权限，但不加密；删除对话时应连同归档与会话文件一起清除 |
| 决定 | 保持默认关闭。已完成一次真实模型配对运行，但结果不完整；补充可核验的回忆样本后再评估是否扩大推荐范围 |

## 交付边界

- 保持 ARTEX 原生 Agent 入口、名称和交互方式；Noa 仅替换上下文压缩实现。
- 保留对话记录、Noa 归档及上传文件的明确删除语义；数据库删除失败时恢复已暂存文件。
- 不新增默认服务、重型依赖或真实目标评测。
- 三项评审记录见[衍生能力三项成本收益评审](../history/【已完成】2026-11-12-衍生能力三项成本收益评审.md)。

## 完成范围与未做事项

- 本计划内的评审与本地代码交付已完成；Go 应用包构建、前端类型检查、详情页 lint 及 CI/Release 前端静态构建通过。按仓库要求未运行测试。
- 交互式 Repeater 请求重放不进入当前自主 Agent 工具链：现有复测能力已覆盖 Agent 主流程，而新增通用发送面会增加目标范围、重定向和 DNS 约束复杂度，当前收益不足以支持这项成本。
- 脚本审批源码快照不做；缺少可保证审批内容与实际执行字节一致的执行机制。
- Noa 保持默认关闭；真实模型配对结果尚不能验证回忆准确性或收益，补充输出受限的记忆核验仍列入待办。

## 当前 Noa 评测安排

- 已完成一组同模型、同 profile 的原生压缩/Noa 配对运行。后续补测应让更新阶段只提供新变化，不重复回忆题中的旧事实，并将最终 JSON 限制为简短字段值，确保输出上限内可核对。
- 补测时记录事实正确率、授权边界、归档回读证据和 token；UI 不显示的请求数与单次延迟应标记为不可得。单次配对结果不用于决定启用默认值。
- 隔离实例模型连接通过 UI 确认。2026-11-25 使用同一模型、profile 与提示完成 Noa 关闭/开启配对：两组首阶段均精确返回 `ACK-1`，更新阶段均返回 `ACK-2`，但附加过程性说明；最终回忆阶段两组均未生成完整 JSON。基线为 5 轮、input 375k/cache 282k/output 1.5k，Noa 为 4 轮、input 360k/cache 270k/output 1.1k。第二阶段重复了多项旧事实，且两组输出上限均为 512，因此目前不能比较回忆准确度或归因 token 差异。UI 未显示单次延迟或准确请求数。评测后 Noa 已关闭，profile 1 原始限额已恢复，产品默认值继续保持关闭；不要在聊天中提交 API Key。
- 2026-11-26 隔离复核发现 UI 内容与预设合成回忆题无关；未运行新的 Noa 会话。待确认 UI 会话数据来源和评测出口边界后，再使用不重复旧事实、输出上限足够的配对提示补测；Noa 保持关闭，profile 原始限额保持不变。

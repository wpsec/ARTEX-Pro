# 【已完成；真实模型评测待恢复】ARTEX 任务约束遵循改进

状态：Router 与 API Skills 的提示词实现已完成并通过静态审查。此归档记录只覆盖实现，不代表真实模型行为回归通过；相关运行时验收仍见[真实模型行为评测记录](../review/【待验证】2026-11-25-真实模型行为评测记录.md)。

## 背景

既有合成环境样本发现了明确任务边界未被稳定遵循的问题：API 盘点任务限定 GET 且禁止资产写入，但执行中出现 HEAD 请求和资产登记；路径发现任务限定最多 8 个 GET，执行结果自报 24 个请求；只读 HTML/BOLA 矩阵禁止文件写入，但结果使用了 `/tmp` 文件。该矩阵明确禁止主动扫描，因此没有启动 ZAP 属于正确遵循，不是遗漏。

## 实施

- Router 规定本次任务中的主机、方法、请求预算、速率、并发、文件/数据库副作用和停止条件优先于通用 Skill 流程；预算按实际网络请求计，包括重定向、重试、浏览器请求和工具校准。
- `api-recon` 保留 `insert_assets` 作为默认交付，仅在用户明确禁止数据库写入时跳过并说明未登记。
- `api-security-testing` 明确尊重本次请求预算和文件写入限制；只在用户授权并要求 API 扫描时使用 ZAP，禁止扫描时不启动扫描器。
- `application-security-testing` 保留范围允许时的资产、事实和漏洞写回约定；只读任务不写库。

## 能力边界

未移除工具、扫描路线或默认测试覆盖；未增加会限制常规测试的全局请求上限。没有改变既有脱敏、证据和报告要求。用户明确限定的范围和副作用要求仍是执行边界。运行时行为尚未通过重新评测证明。

以上变更属于 ARTEX 原生 Skill 的行为指引，不是网络层请求计数器或目标出口硬拦截。它们不能单独证明模型会遵守限制，也不能解决评测实例的会话数据来源与网络隔离疑点。

## 版式修订

ARTEX 是在授权范围内运行的 AI 自主渗透测试系统。交付正文面向开发人员，要求简短、能定位问题、能验证修复。更新后的版式在「测试过程」下记录三项需求。

1. **Burp 复现包**。说明实际验证状态，并给出已有测试记录的查阅位置。
2. **攻击链路**。概括功能入口、未生效的校验及实际业务影响。
3. **复现脚本（Python）**。显示附件状态。有现成的 Python 修复回归用例时，记录用例位置和预期结果。

新版顺序同时用于报告预览和复制。任务 16 的 5 份报告均通过新版顺序的只读核对。Chromium 验证了预览与复制使用相同版式。Burp 小节显示测试记录引用，Python 小节显示附件状态和已有复测标准的位置。Burp 原包及可复现漏洞的 Python POC 生成和导出尚未交付。

## 新任务报告生成

报告 Agent 和结构化草稿入口统一使用简短的正文写法。描述说清功能、权限和已观察的影响。测试过程先写预期和实际结果，仅在影响结论时提及失败和未验证范围。修复建议说清应改的校验点与验收预期。

生成草稿和报告 Agent 保存正文时，系统会整理部分常见台账写法。测试序号与非零长度注记从叙述中去掉，零长度注记写为没有内容。代码块、攻击链和原始附录沿用原有流程。已有报告和人工保存的正文按原样存储。已知旧默认提示词随版本更新，自定义提示词保留。

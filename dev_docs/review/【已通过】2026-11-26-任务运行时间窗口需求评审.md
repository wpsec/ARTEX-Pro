# 【已通过】任务运行时间窗口需求评审

用户希望在创建任务时配置一个每日执行时段，也能在主对话中调整时段。例如某任务只允许在当天 22:00 至次日 08:00 运行，到 08:00 暂停。

## 评审结论

2026-11-26 用户确认将时间窗口作为任务的执行限制。窗口关闭时暂停，窗口打开后由有权限的人确认开始或继续。[实施计划](../history/【已完成】2026-11-26-任务运行时间窗口实施计划.md) · [实现复审](../history/【已完成】2026-11-26-任务运行时间窗口复审.md)

## 现有能力

- 创建任务已经接受以秒计的超时。当前截止时间按首次开始时刻加超时秒数计算，可能落在窗口暂停期间。创建界面需要分别展示运行时段与任务的截止时间。[创建请求](../../server/server.go#L1479) · [截止时间计算](../../db/tasks.go#L507)
- 任务列表已提供手动暂停、继续及排队状态，可以复用现有状态与操作入口。需要为窗口限制提供独立提示，使用户区分人为暂停、窗口关闭和并发排队。[任务列表](../../web/src/app/%28main%29/function/tasks/page.tsx#L245)
- 现有暂停会持久化状态、撤销排队并通知在途工作取消。暂停接口返回时，在途工作可能仍在退出。归档和删除已有等待任务静止的检查，可作为判定「已暂停」的依据。[持久化暂停](../../server/manager.go#L1281) · [暂停控制](../../server/task_control.go#L96) · [等待静止](../../server/server_mgmt.go#L202)

## 建议范围

| 项目 | 验收口径 |
|---|---|
| 创建任务 | 支持可选的每日开始时间、结束时间和 IANA 时区。启用限制的任务保存后等待人工开始。 |
| 主对话配置 | 用户指明唯一任务后，主对话展示任务、原时段、新时段及时区，由有权限的用户确认保存。保存只更改时间窗口。任务指代有歧义时先请用户选择。 |
| 跨午夜 | 支持一段跨午夜的每日窗口，开始包含、结束排除。以 `Asia/Shanghai` 的 `22:00–08:00` 为例，22:00 允许人工开始，07:59 在窗口内，08:00 进入暂停。开始和结束相同时提示重新选择。 |
| 编辑生效 | 保存窗口设置后立即按新窗口判断。新窗口已关闭时暂停并显示原因；窗口重新打开后显示可人工继续。 |
| 排队跨过截止 | 在窗口内由人工确认后进入并发队列的任务，如果截止时仍在等待，则撤销排队。下一次进入窗口时重新由人工确认。 |
| 窗口关闭 | 截止时刻拒绝新的执行请求，并尽快取消已受控的在途工作。界面在在途工作退出前显示「暂停中」，退出后显示「已暂停」。对外部服务已接收的请求，以实际结果和审计记录为准。 |
| 任务超时 | 每日窗口按时段控制是否可以执行。已有任务超时按首次开始后的经过时间计算，界面分别显示窗口关闭时间和任务截止时间。 |
| 持久化与审计 | 重启后按保存的时区和时间重算窗口状态。审计记录操作人、任务、原值、新值和生效时间。任务列表显示当前窗口状态及下一边界时间。 |

## 验收重点

1. 用可控时钟验证同日窗口、跨午夜窗口、开始与结束边界、无窗口以及时区变化。
2. 验证窗口关闭时拒绝人工开始或继续，窗口开启只改变可执行提示，保留人工暂停语义。
3. 验证运行中修改窗口、排队跨过截止、超时截止落在暂停期间、关闭时仍有在途工作和服务重启等情形，核对状态、人工确认和审计结果。
4. 验证创建界面和主对话的配置一致。覆盖无权限操作、用户取消、指代多个任务、旧配置已被修改，以及持久化后重新加载。
5. 使用合成任务和模型替身完成离线验收。评审通过后确定实现拆分和交付检查。

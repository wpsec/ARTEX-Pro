# 【待用户审计】网络空间搜索引擎需求评审

## 评审结论

**配置管理与人工被动核验有条件通过技术评审。** 建议接入九个独立的数据源，在系统「工具」下方新增「网络空间搜索引擎」配置入口。配置页支持只写凭据和批量连接测试。资产核验由人员对已授权、已登记的资产发起，查阅第三方已有记录。自主发现目标、对目标发起探测或漏洞测试、把查询结果交给执行 Agent 的部分不纳入实施计划。Skill 可用于解释人员选定的证据摘要，使用来源、观测时间和缺失字段说明证据局限。[实施计划](../plan/【待用户审计】2026-11-27-网络空间搜索引擎实施计划.md)

## 待用户审计

| 决策 | 确认后生效的范围 |
| --- | --- |
| 第一阶段已通过 | 用户确认开发九家供应商配置页与连接测试。凭据操作沿用 LLM 的习惯，使用同一个 PostgreSQL 配置库。涉及真实账户的验证按已授权的账户执行。 |
| 是否启动第二阶段 | 可开发人工资产核验与结果解读 Skill。先确认从哪里取得人工批准的任务授权，以及谁有权确认外发。仅批准第一阶段时，设置页和连接测试可独立交付。 |
| 哪些供应商可接收资产标识 | 确认允许外发的供应商、资产字段及适用套餐或数据许可。可以逐家确认。缺少外发许可的来源仍可保留配置，在资产核验页不可选。 |

2026-11-27 用户提出在任务创建时逐家选择供应商，默认勾选已配置来源，并用红字提示外发影响。逐家选择可在第二阶段评审中作为查询偏好；实际外发前由人员确认单条已登记资产、接收供应商及外发的字段。任务描述或默认勾选本身不足以证明已批准该笔外发。基于结果自动拓展目标、发起探测和漏洞测试未纳入实施。后续 Skill 逐家整理数据类型、字段含义、观测时间和套餐限制，用于说明操作者选定的结果。

## 配置与测试体验

- 系统菜单中紧接「工具」添加「网络空间搜索引擎」。入口用简化的地球经纬线与放大镜，沿用 ARTEX 蓝紫色系及现有侧栏图标尺寸。页面标题、图标及「测试全部」按钮放在页首，供应商以紧凑列表展示，窄屏换行。每行显示引擎名、配置状态、最近测试结果和时间。点击配置后展开独立编辑面板。[现有侧栏](../../web/src/app/%28main%29/_components/sidebar/app-sidebar.tsx#L39) · [ARTEX 标识](../../web/public/logo.svg)
- API Key 或 Token 只写。保存后清空输入框，刷新后只显示「已配置」或「未配置」。编辑其余字段时留空表示保留，填写新值表示替换，清除凭据为明确的独立操作。供应商要求的其他账户标识仅在有必要时收集，默认也不回显。
- 「测试全部」测试已配置且启用的来源，逐家给出「通过」「失败」「未验证」或「已跳过」及简短原因。失败区分凭据错误、权限或套餐不足、限流、超时及上游故障。凭据轮换、禁用或清除后，旧结果失效。通过只表示文档所列的账户、鉴权或可用性检查成功，具体查询权益仍以账户套餐为准。
- 批量测试使用已保存配置且不携带任务资产。优先用官方鉴权、账户或套餐检查；只有搜索接口可用、缺少必要账户标识，或无法证明检查会验证 API Key 时，显示「未验证」及原因。不用任意域名或 IP 兜底，也不从历史任务取样。合成回包只用于离线测试。

## 人工资产核验及 Skill

- 用户从已有资产记录选择单条已授权的完整域名、单个公开 IP 或已登记证书指纹，并选择有对应数据能力的来源。在发送前展示将外发的标识和接收供应商。私有地址、内部名称、未登记资产以及无法确认归属或外发权限的记录不进入请求。域名、IP 和证书按供应商及套餐逐项验收，证书按已有指纹做匹配。
- 展示最小必要的结构化字段和来源时间，作为资产维护人员的核验记录。通过域名、IP 或证书发现的其他实体不作为下一轮输入，也不自动入库。授权变更后重新检查访问权限。上游内容作为不可信数据处理，忽略其中的命令、链接指令和提示词。
- Skill 为可选说明文档，仅帮助 ARTEX 解读用户主动选入对话的脱敏结果，解释时间差、来源差异以及证据缺口。Skill 不接收凭据，不提供调用供应商、批量发现或触发测试的入口。

### 各供应商的 Skill 解读草案

Skill 的输入限定为操作者选定的结构化观察，包括来源、所查资产标识、观察对象、查询时间、上游观测时间和必要字段。输出区分「有记录」「无记录」「字段缺失」「无法归属」，保留来源及时间。多个供应商观察不一致时分别列出依据。

| 供应商 | 从已选观察中解释的内容 |
| --- | --- |
| FOFA | 区分域名、证书和服务观察。SSL 证书复用或服务信息过旧时标出归属待人工核对。[FOFA API](https://fofa.info/api) |
| 奇安信鹰图 | 区分平台返回的原始主体与关联线索。当前套餐和时间字段的定义须用官方资料或授权样本核对。[鹰图帮助中心](https://hunter.qianxin.com/home/helpcenter) |
| hunter.how | 展示供应商返回的更新时间与资产标识。更新日期缺失时标记未知，区分证书记录和同一资产的服务记录。[hunter.how API 文档](https://hunter.how/search-api) |
| Shodan | 将服务信息标为外部历史观测，保留观测时间，避免与 ARTEX 当次主动测试的结果混用。[Shodan API 文档](https://developer.shodan.io/api) |
| ZoomEye | 先读明返回对象属于哪个数据类型，再解释字段。套餐或数据类型未提供的字段标记缺失。[ZoomEye API 文档](https://www.zoomeye.ai/doc) |
| 360 Quake | 对域名和服务信息分别保留来源。只有供应商实际返回的观测字段才作为证据显示。[Quake 官方客户端](https://github.com/360quake/quake_rs) |
| VirusTotal | 将域名与 IP 的历史分析结论分别说明，保留分析时间。第三方引擎的分类属于信誉情报。[域名对象](https://docs.virustotal.com/reference/domains-object) · [IP 对象](https://docs.virustotal.com/reference/ip-object) |
| ProjectDiscovery Chaos | 解释为 DNS 数据集中的历史线索，标出时效和归属仍待人工确认。[Chaos 文档](https://chaos.projectdiscovery.io/docs) |
| SecurityTrails | DNS 或注册信息按记录来源和时间分别解释，历史记录与当前查询时刻分别标记。[SecurityTrails API 概览](https://docs.securitytrails.com/docs/overview) |

供应商真实账户及套餐仍待验证。本记录的供应商能力判断以公开文档为依据。

# 交付报告规范

交付报告面向开发和业务人员，说明问题、复现方法、实际影响和修复办法。详细报告留存完整测试台账；交付报告只保留读者理解和处理问题所需的信息。

## 固定结构

```markdown
# <系统或模块> <功能或接口> <缺陷>：<实际影响>

CVSS 4.0：<完整 Base 向量> 评分 <分数>（<等级>）

## 描述
<问题、成立条件和实际业务结果>
### 定级依据
<权限条件及已观察影响如何支持评分>

## 修复建议
<针对已确认问题的修复办法和预期行为>

## 测试过程
### 发现过程与攻击思路
<最短复现步骤、必要账号或条件、关键请求或命令及判据>
### 失败尝试与未验证项
<影响结论的实际失败和未验证边界>
### Burp 复现
<说明是否实际使用 Burp Repeater；HTTP 报告必须附至少一段最小必要请求包。实际使用时附实际发送的请求；未使用时标记为未发送的建议复测请求>

## 攻击链路
~~~text
<入口或已知起点>
└─ <请求或命令>
   └─ <观察到的结果>
~~~

## 证据说明
<材料来源、完整性和缺失内容>
### 复测标准
<修复成功时可观察到的结果>
```

## 写作要求

- 用简短、常见的中文说明实际情况。先写问题和业务结果，删除重复台账、内部流程标签和不必要的背景。
- 测试过程以业务结果为主。报文长度、逐字节比较、内部序号、日志标签、文件具体属主和工具内部判定属于测试台账。
- 新生成的描述、测试过程和修复建议在保存时按事实字段整理。描述写已确认的后果，材料无法确认的情况放入测试过程的「未验证范围」。修复建议分别保存修复措施和验收预期。模型分工、发现合并关系和原文哈希留在详细报告。
- 结论以原始报文、命令输出和执行记录为依据。旧报告和 worker 总结只用于找线索；没有记录的账号、工具、页面入口、失败尝试或影响不补造。
- 详细报告保留工具参数、逐项时间、失败日志、哈希和证据索引。交付报告只写复现必需的账号、请求或命令、操作顺序和判据。
- 测试过程首行写测试时间并注明北京时间，优先采用执行记录。流量采集时间只说明对应请求的时间，不代表漏洞首次发现时间或完整测试时段；没有可靠时间时写“测试时间：未记录”，不得用报告生成时间代替。竞态、令牌有效期等时间关系会影响结论时，在对应步骤保留准确时间。详细报告继续保留完整时间台账；原始报文和日志保持原样。
- 描述区分已观察结果与未验证影响。状态码、响应头或身份标记不能单独证明未授权访问或数据泄露；响应正文缺失时说明缺口。
- 修复建议针对已确认问题。没有源码或配置证据时，不猜文件、版本或现有实现；业务约定与观察结果足以确定修复目标时，可提出一项直接措施，并注明源码位置或现有实现未核实。行为或安全缺陷尚未确认时，先列补证，不给代码修复结论。没有找到撤销操作不等于无法恢复；返回文件信息不等于已验证文件内容。
- 攻击链只连接证据支持的入口、必要条件、请求或命令和实际结果。页面来源未知时从接口开始，不补造前端操作或服务端实现。
- 生成时，ARTEX 会从已绑定的原始请求提取 METHOD/path 索引，帮助模型准确引用接口。索引不替代或改写原始报文；相同路径出现多次也不能单独证明重复利用或并发。
- HTTP 问题在“测试过程”说明 Burp Repeater 的实际使用情况，并始终附至少一段足以复测核心结论的最小请求包。实际使用时附实际发送的请求；未使用时标明复测未验证，并把请求包标为“建议复测请求（未发送）”。并发问题不得用 Repeater 串行重放证明并发。非 HTTP 问题写实际命令，并说明 Burp 不适用。
- 请求包优先保留有证据的 METHOD/path、参数、正文、Host 和必要请求头；Authorization、Cookie、Token、会话标识及个人数据须使用用途明确的占位符。材料缺少字段时仍附带占位符的请求模板，并指出需重新捕获的字段；材料没有 METHOD/path 时使用占位符请求行，明确模板不完整且不能直接发送，不得猜造。
- 避免测试脚本内部术语和难懂缩写，如“六腿差分”“阴性对照”“401/144B”“held=”。状态码或响应长度对结论有用时，用中文写清它表示什么；攻击链的结果节点说明业务状态，不只列数字或变量名。
- 完整绑定的 HTTP 请求和响应由 ARTEX 原文附加在报告末尾，正文不重复响应正文；Burp 小节可重复一条已脱敏的最小请求包供复测。平台外报文只有在完整留存时才按真实来源引用；只有路径、片段或缺少响应正文时说明材料缺口。
- 合成样本说明未测试真实目标。合成身份标记不代表真实认证凭证。

## 交付验收

- 任务结束、发现登记和报告保存分别核对。正式交付前确认详细报告和交付报告均已保存、CVSS 4.0 评分有效、证据版本一致。
- HTTP 分项的复现章节缺少完整报文时，明确标记缺项并保留为草稿。流量条数仅用于核对证据。

## 保存与评审

Reporter 仍由 `report_finding` 触发，通过现有 `update_finding_report` 一次保存详细报告和交付报告。保存校验检查标题、固定章节与子标题、攻击链结构、CVSS 向量一致性、证据版本和完整性；不通过关键词列表判断文风或语义，不自动截断或改写原始证据。

默认提示词迁移只更新与已知旧默认完全相同的内容，保留用户自定义提示词。历史报告不会被自动覆盖。固定样本覆盖越权、注入、并发、登录会话、非 HTTP 和证据不完整场景；格式测试不替代对模型样稿的逐份阅读。

评测方法见 [报告评测](../tools/report-eval/README.md)。
